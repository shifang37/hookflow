# v0.2 验收清单

主题：**把"能跑"变成"有测试保障"。** 判据是——v0.1 里的每一条可靠性主张，现在要么有一个可重放的自动化测试，要么有一次真实演练记录；**两者不能互相替代**。

状态：✅ 已完成 · ⚠️ 部分完成（有明确后续）· ⬜ 未开始（已排到 v0.3）

---

## A. 测试能力（v0.2 的核心）

| 项 | 状态 | 证明材料 |
|---|---|---|
| 测试总数从 34 增长到 67 | ✅ | 47 单元 + 20 集成，`./mvnw verify` |
| 引入属性测试（jqwik） | ✅ | 16 个属性：退避抖动区间、签名完整性、订阅匹配、IPv4 范围分类 |
| 属性测试真的抓到了问题 | ✅ | IPv4 `240.0.0.0/4` 保留段未被拦截，被属性测试穷举发现后修复 |
| 接收方侧故障注入 | ✅ | `ReceiverFaultIT`：慢响应 → `TIMEOUT`；拒绝连接 → `CONNECT_ERROR`；故障消失后同一个 delivery 自动成功 |
| broker 侧故障注入 | ✅ | `BrokerOutageIT`：冻结期间事件仍被接受、零 attempt、工作停在 outbox；恢复后自动追平且只尝试一次 |
| 崩溃窗口的确定性重建 | ✅ | `OutboxCrashWindowIT`：sweeper 重新武装 + 消息重复 + attempt 护栏吸收，接收方只看到一次尝试 |
| 故障注入不依赖不可靠的时序 | ✅ | 崩溃窗口通过直接构造 PUBLISHING + 旧时间戳重建，不靠 race |
| CI 可跑 | ✅ | `./mvnw verify` 覆盖全部 67 个测试 |

## E. 明确的技术债

| 债务 | 影响 | 计划 |
|---|---|---|
| 无背压 / 无租户公平调度 | 大租户可饿死小租户，突发可打满 worker | v0.3 |
| 固定窗口限流 | 窗口边界 2 倍突刺 | v0.3 |
| 无分布式 trace | 跨 api→worker 定位慢投递只能靠 requestId + 日志 | v0.3 |
| 无压测数据 | 不能说"高并发" | v0.3 |
| SSRF 只做创建时校验 | DNS rebinding 可绕过 | 待定 |
| `stale-publishing-seconds` 一值两用 | 崩溃窗口宽限期与卡死兜底需求不同 | 出现真实误判再拆 |

## 一句话自评

**现在可以讲的**：投递语义与崩溃窗口、故障注入测试、真实演练的实测数字、SSRF 与密钥管理的取舍、三个自己踩出来的 P1 缺陷。
**还不可以讲的**：性能数字、多租户公平性、跨服务链路追踪。

后者正是 v0.3 的全部内容。
