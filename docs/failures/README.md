# 故障与缺陷记录索引

这个目录记录**真实发生过**的故障、缺陷、以及每一次故障演练的观察结果。

## 为什么单独建目录

大多数项目只在 commit message 或 issue 里留一句 "fix bug"。但对一个主打可靠性的项目来说，**最有价值的信息是"你曾经在什么地方出错"**——因为：

1. 它证明你真的跑过系统，而不只是把它写出来
2. 复盘的结构（现象 → 根因 → 修复 → 回归）本身就是工程能力的体现
3. 三个月后回看，你能记得当时的判断依据，而不是只记得"改了一行"

## 约定

- 一个事件一个文件，命名 `NNNN-短标题.md`（例如 `0001-relay-crash-duplicate.md`）
- 模板见 [TEMPLATE.md](TEMPLATE.md)
- **只记录真实发生的**。故障演练在"状态"字段标 `演练`；线上/本地真实踩的 bug 标 `缺陷`
- 不确定的地方写"未确认"，不要编造根因
